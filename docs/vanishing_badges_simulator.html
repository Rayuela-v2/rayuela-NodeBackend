Badge Grid Cells (12 Columns):

Each badge cell $(p, b)$ displays the player's Individual Interest score $i_3(p, b)$ (Def 3.2), calculated as $\frac{1}{now - t_0}$. If the badge is already earned, it shows ✔ d[day] indicating it belongs to the player's earned set $B_p$. If prerequisites are missing, it displays 🔒 ($b \notin AB(p)$).

Player Summary Columns (Right 3 Columns):

These columns aggregate the player's status across sets:
• $|B_p|$ (Earned Badges Count): Total badges won by player $p$ ($B_p$ is the earned set in Def 3.3: $AB(p) - B_p$).
• $|AB(p)|$ (Achievable Badges Count): Badges whose prerequisites are completed (Def 3.1).
• $|ignored\_by(p)|$ (Ignored Badges Count): Badges in $AB(p) - B_p$ neglected with $i_3 < x$ (Def 3.3).

Definition 3.1: Achievable Badges ($AB(p)$) NEW DEF 3.1 Prerequisite State
$$AB(p) = \{\, b \in \text{Badges} \mid \forall prev \in \text{prerequisites}(b),\, prev \in B_p \,\}$$

A badge is achievable to a player when all previous badges (prerequisites) have been earned. Root badges without prerequisites are achievable to everyone upon joining.

Definition 3.2: Individual Interest Indicator ($i_3$) Recency Metric
$$i_3(p, b) = \begin{cases} \dfrac{1}{now - t_0} & : b \in AB(p) \\[6pt] 1 & : b \notin AB(p) \end{cases}$$

Inverse of elapsed time since $t_0$ (the timestamp when player $p$ met prerequisites for badge $b$). As time passes without player $p$ earning the badge, $i_3$ drops toward $0$.

Definition 3.3: Ignored Badges NEW DEF 3.3 Neglect Set
$$ignored\_by(p) = \{\, b \in AB(p) \setminus B_p \mid i_3(p, b) < x \,\}$$

The set of badges achievable by player $p$ that have not yet been earned ($AB(p) - B_p$) whose individual interest has fallen below reference threshold $x$.

Definition 3.4: Community Interest Indicator ($CII$) RENUMBERED 3.4 Community Metric
$$CII(b) = \operatorname{median}(\{\, i_3(p, b) \mid p \in ep(b) \,\}) \quad \text{where } ep(b) = \{\, p \in P \mid b \in AB(p) \setminus B_p \,\}$$

Median of individual interest scores among all players who are currently eligible for badge $b$.

Section 4.1: Adaptation Trigger NEW REVISED TRIGGER Trigger Rule
$$\text{Trigger Adaptation} \iff \exists b \in \text{Candidates} : CII(b) < x$$

"The adaptation must be triggered when a badge is detected to be ignored by the community. This is, when community interest falls below a reference value ($\exists b : CII(b) < x$)."

Evaluation Framework (Section 5 — Torres & Dalponte Ayastuy)

Methodological structure designed to validate the Vanishing Badges adaptation across three complementary pillars: Adaptabilidad, Usabilidad, and Efectividad.

1. Adaptabilidad

Dynamic
¿Realmente ocurre que el sistema se adapta? ¿Su comportamiento depende de la interacción con una comunidad específica?

Evaluates whether the indicators respond reactively to community dynamics:

  • ✔ Trigger detection when $\exists b : CII(b) < x$
  • ✔ Target badge ranking based on lowest $CII(b)$
  • ✔ Candidate filtering ($badges - all\_player - ur$)

2. Usabilidad

UX Instruments
¿Las personas se sienten cómodas? ¿Perciben que las recompensas, desafíos y niveles son adecuados?

Standardized instruments recommended by the paper to evaluate player perception:

  • 📊 System Usability Scale (SUS)
  • 📋 User Experience Questionnaire (UEQ)
  • 🗣 Qualitative Think-Aloud protocols

3. Efectividad

Impact Metric
¿La ludificación aumenta la motivación y el compromiso? ¿La adaptación mejora el desempeño o cumplimiento de objetivos?

Measured via the volume of check-in interactions recorded and recovery of neglected tasks:

  • 📈 Interaction surge during adaptation window
  • 🎯 Recovery rate of neglected citizen science tasks
  • 🌐 Long-term community retention & spatial coverage
